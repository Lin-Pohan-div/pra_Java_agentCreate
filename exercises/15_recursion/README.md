# 15 遞迴

> 難度：★★★　主題：遞迴、終止條件、演算法

## 學習目標

- 理解遞迴：方法呼叫自己，去解決一個規模更小的同類問題
- 每個遞迴都要寫出**終止條件**（base case）
- 確認每次遞迴都會讓問題「更接近」終止條件
- 會把數學定義直接翻譯成遞迴程式

## 觀念講解

### 遞迴的兩個部分

```java
public static int countDown(int n) {
    if (n == 0) {                 // 1. 終止條件：不再呼叫自己
        return 0;
    }
    return 1 + countDown(n - 1);  // 2. 遞迴步驟：把問題縮小
}
```

只要少了其中一個，或遞迴步驟沒有讓問題變小，呼叫就會無止盡地疊下去，最後丟出 `StackOverflowError`。

### 翻譯數學定義

很多遞迴函式本來就是用遞迴方式定義的。例如 `x` 的 `n` 次方：

```
power(x, 0) = 1
power(x, n) = x × power(x, n - 1)
```

翻譯成 Java 幾乎是一對一：

```java
public static int power(int x, int n) {
    if (n == 0) {
        return 1;
    }
    return x * power(x, n - 1);
}
```

寫遞迴時，先把定義寫成上面這種「條件 → 結果」的形式，再照抄進程式。

### 拆解數字

`n % 10` 可以取出個位數，`n / 10` 可以去掉個位數。這兩個運算很適合拿來把一個數字逐位拆解：

```java
// 計算有幾位數
public static int digits(int n) {
    if (n < 10) {
        return 1;
    }
    return 1 + digits(n / 10);
}
```

### 追蹤呼叫過程

不確定遞迴對不對時，把呼叫一層一層寫下來：

```
power(2, 3)
= 2 * power(2, 2)
= 2 * (2 * power(2, 1))
= 2 * (2 * (2 * power(2, 0)))
= 2 * (2 * (2 * 1))
= 8
```

如果某個式子的參數永遠不會到達終止條件，或兩次呼叫後又回到原點，就找到問題了。

## 常見錯誤

- 沒有終止條件，或終止條件永遠不會成立
- 遞迴呼叫的參數沒有「變小」，呼叫好幾層之後又回到原本的參數
- 把數學定義翻譯錯，參數的位置或運算寫錯
- 遞迴結果算出來了，卻忘了 `return`

## 延伸（選讀）

- 最大公因數的**歐幾里得演算法**：兩個數的最大公因數，等於「較小的數」和「兩數相除的餘數」的最大公因數；餘數為 0 時，答案就是除數。可以試著先用 48 和 18 手算一遍。
- 天真的費氏數遞迴會重複計算同一個值，`fib(40)` 就會明顯變慢。可以用陣列或 `Map` 記住算過的結果（memoization），或改成迴圈。
